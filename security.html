Security

Security begins with verification.

The website cannot protect a user who signs a malicious transaction, shares a seed phrase or sends funds to the wrong network. These practices reduce avoidable risk.

✓

Verify the contract

Use TV714TT9aQftbkYBjWiVExCxNZm9nPJX6K. Ignore lookalike tokens with similar names or icons.

⌁

Verify the destination

Check the network, recipient address and transaction preview before signing. Use a small test where appropriate.

⊘

Never share secrets

No legitimate admin needs your seed phrase, private key or recovery code. Keep them offline and private.

Phishing

Trust links less. Verify destinations more.

Search ads, fake social accounts, copied Telegram profiles and cloned websites are common attack paths. Bookmark the project website and confirm the contract via multiple independent sources.

Smart-contract risk

Public does not mean risk-free.

Blockchain code and token integrations can contain bugs or design risks. The absence of an audit badge should never be interpreted as an audit.

No support agent should ask for wallet secrets. If someone asks you to “validate” or “sync” a wallet by entering a recovery phrase, treat it as malicious.
